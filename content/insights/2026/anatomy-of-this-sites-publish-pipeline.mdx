Publishing on this site is one MDX file and a `git push`. Everything between
the push and the page being live on CloudFront is automated, validated and
credential-free. This post walks the pipeline end to end.

## Stage 1: the content contract

Every post starts as MDX with YAML frontmatter. At build time, Velite
validates the frontmatter against Zod schemas — title length, description
length (it doubles as the meta description, so 160 characters max), an ISO
date, and tags that must exist in a controlled taxonomy file:

```ts
const tags = s
  .array(s.enum(TAG_SLUGS as [string, ...string[]]))
  .min(1)
  .max(4);
```

An unknown tag or a missing field fails the build. Malformed content cannot
reach production — the same philosophy as a Terraform `validation` block, just
pointed at prose instead of infrastructure.

## Stage 2: static export

Next.js builds the entire site to plain HTML, CSS and JS. There is no server:
every article, tag page and series page is generated by
`generateStaticParams` — a template multiplied by a list, exactly like a
Terraform `for_each`. Pagefind then indexes the rendered HTML into a static
search index that ships with the site. Three posts or three hundred, the
publishing workflow never changes.

## Stage 3: deploy without credentials

GitHub Actions assumes an AWS IAM role via OIDC federation. There are no
long-lived access keys anywhere — the trust policy pins the token's `sub`
claim to this repository's `main` branch, and the role can do exactly two
things: sync one S3 bucket and invalidate one CloudFront distribution.

## Stage 4: caching that never goes stale

The sync step splits the upload in two:

- Hashed immutable assets (JS chunks, images) get
  `cache-control: max-age=31536000, immutable` — cached for a year.
- HTML, sitemap and feeds get `max-age=0, must-revalidate` — always fresh.

This is safe because every asset filename contains a content hash. Change an
image and its URL changes with it: cache busting falls out of the design for
free, the same way immutable infrastructure sidesteps configuration drift.

## Why this shape

Total moving parts in production: an S3 bucket and a CDN. Monthly cost:
roughly the price of a coffee refill. Operational overhead: zero. The
pipeline is strict where mistakes are cheap to catch (build time) and boring
where incidents are expensive (runtime) — which is the whole point of
platform engineering.
