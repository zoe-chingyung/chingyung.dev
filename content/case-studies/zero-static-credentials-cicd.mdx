## Context

CI/CD pipelines traditionally authenticate to AWS with long-lived access keys
stored as repository secrets — keys that never rotate, leak in logs, and grant
far more than the pipeline needs.

## Problem

Deploy this site from GitHub Actions with no static credentials anywhere, and
with blast radius limited to exactly what a deployment requires.

## Constraints

- Single AWS account, personal project budget
- Terraform must manage the trust configuration itself
- Approval gates for anything touching infrastructure

## Design decisions

Three IAM roles, each trusting GitHub's OIDC provider with conditions on the
repository and ref claims: a read-only **plan** role for pull requests, a
least-privilege **deploy** role (S3 sync + CloudFront invalidation, main
branch only), and an environment-gated **apply** role for Terraform.

## Implementation

The trust policy pins the `sub` claim to `repo:<owner>/<repo>:ref:refs/heads/main`,
so a workflow in any other repository or branch cannot assume the role even
inside the same AWS account.

## Lessons learned

The OIDC setup cost one evening; eliminating credential rotation pays that
back permanently. Scoping the apply role tighter than `AdministratorAccess`
remains an open improvement.
